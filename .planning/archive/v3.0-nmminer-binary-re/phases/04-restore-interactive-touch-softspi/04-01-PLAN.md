<objective>
Restore the CYD's XPT2046 touchscreen at the BUS layer: enable touch for the
`ESP32-2432S028R` env and drive the controller over a software/bit-bang SPI on the
touch pins, NOT the hardware VSPI peripheral (D-42, the touch-before-SD bus lock).
Read raw Z-pressure / raw X/Y first (D-43) so a later on-device session can prove the
bus works before calibration is trusted, then map raw→pixel for rotation 1, 320x240,
using the known CYD calibration range (D-44).

Purpose: The fork's `TouchHandler` is compiled OUT for the CYD env, and the only
existing instance (`t_hmiDisplayDriver.cpp`) binds the hardware `SPI` (VSPI) via the
`arduino_xpt2046_library` — which is a hardware-SPI library with no bit-bang mode. D-42
forbids VSPI here (SD claims it in Phase 6). The clean, D-42-compliant path is a small
direct bit-bang XPT2046 reader. This is on-device-test-free: the gate is BUILD SUCCESS +
a documented raw-Z diagnosis path (on-device tap is Phase 7).

Output: `src/ui_nm/nm_touch.{h,cpp}` (SoftSPI XPT2046 driver) + platformio.ini env
enablement; the env compiles touch IN and links.
</objective>

<interface_context>
Pin macros are defined in `[env:ESP32-2432S028R]` build_flags (platformio.ini ~991-1002):
`ETOUCH_CS=33`, `TOUCH_CLK=25`, `TOUCH_MISO=39`, `TOUCH_MOSI=32`, `TOUCH_IRQ=36`,
`SPI_TOUCH_FREQUENCY=2500000`. These exist already — the env just never defined
`TOUCH_ENABLE`, so `TouchHandler` (`#ifdef TOUCH_ENABLE`) compiled out.

XPT2046 SPI protocol (the 3 control bytes nm_touch must bit-bang, MODE0, MSB-first,
~2.5 MHz max so a plain digitalWrite loop is fine):
- Z1 pressure: control byte `0xB0` (read 12-bit), then read Z2 `0xC0`; pressure ≈ Z1 - Z2 (or use Z1 with a threshold).
- X: control byte `0x90`. Y: control byte `0xD0`. Each returns a 12-bit value in the two bytes after the command (shift the 16-bit read right by 3).
- Sequence per read: CS low → send cmd byte → read 2 result bytes (16 clocks) → CS high.

nm_touch must NOT instantiate `SPIClass`/`SPI`/`VSPI` and must NOT include `<xpt2046.h>`
(both bind hardware peripherals). Use raw `pinMode`/`digitalWrite`/`digitalRead`.

CYD calibration range (rotation 1, 320x240) starting point from RNT/marcelrv CYD
examples: raw X ~ [200..3700] → pixel X [0..319]; raw Y ~ [240..3800] → pixel Y [0..239].
Store as named constants in nm_touch.cpp; expose so they can be tuned later (D-44).
Verify axis orientation against the panel's setRotation(1); swap/invert constants as
needed and note it (the t_hmi handler's bottom/top split @ TouchHandler.cpp:41 is a hint
about its axis mapping, but it uses different rotation — do not copy its thresholds blindly).
</interface_context>

    `arduino_xpt2046_library` were CONSIDERED. They are NOT reused for the bus layer because

    grab VSPI and violate D-42. The gesture/debounce SHAPE of TouchHandler is mirrored in
    Plan 04-02, not here. So nm_touch is a new bit-bang bus reader, not a parallel reimpl of
    gesture logic.

    Header `nm_touch.h` (extern "C") declares: `void nm_touch_init(void);`
    `bool nm_touch_pressed(void);` `uint16_t nm_touch_raw_z(void);`
    `bool nm_touch_read_raw(uint16_t* rx, uint16_t* ry);`
    `bool nm_touch_read_point(int16_t* px, int16_t* py);` (calibrated pixel, rotation 1) and
    `void nm_touch_log_raw(void);` (D-43 serial diagnosis dump).

    `nm_touch.cpp`: implement bit-bang SPI on `TOUCH_CLK`(25)/`TOUCH_MOSI`(32)/`TOUCH_MISO`(39)/
    `ETOUCH_CS`(33) — pinMode in `nm_touch_init` (CLK/MOSI/CS OUTPUT, MISO INPUT; CS idle HIGH).
    Do NOT instantiate SPIClass and do NOT include <xpt2046.h>. Write a `xpt_xfer(uint8_t cmd)`
    helper that pulses CLK manually (MODE0, MSB first, ~2.5 MHz is the ceiling — a tight
    digitalWrite loop is well under that). `nm_touch_raw_z` reads Z1(0xB0)/Z2(0xC0) and returns
    a pressure proxy. `nm_touch_read_raw` reads X(0x90)/Y(0xD0) 12-bit values; take a small
    median (3-5 samples) to denoise. `nm_touch_pressed` = raw_z above a documented threshold
    (TOUCH_IRQ GPIO36 is input-only with no pull — default to POLLED pressure per D-41; do not
    rely on IRQ). `nm_touch_read_point` maps raw→pixel using named calibration constants
    (CYD rotation-1 range from interface_context); clamp to [0,319]/[0,239]. `nm_touch_log_raw`
    Serial.printf's raw Z/X/Y + mapped pixel (the D-43 gate evidence; called from a debug seam
    in 04-02). Document in a header comment that VSPI is deliberately left free for SD (D-42).
