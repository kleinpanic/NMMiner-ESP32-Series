<objective>
Implement a custom JSON web API that exposes mining status, speaker controls, and SD file operations. This API replaces/extends the stock NMMiner API and is the contract between firmware and dashboard.

Purpose: Define a clean, versioned API that the dashboard understands. The API aggregates mining stats (from the core), speaker state, and SD filesystem info into a single response. Later, the dashboard will repoint to this API.

Output: Functional API endpoints, proper JSON serialization, input validation, response codes.
</objective>

<task type="auto">
  <name>Task 3: Implement api.cpp with JSON response builders</name>
  <files>firmware/custom/NerdMiner-CYD-Custom/src/api.cpp</files>
  <action>
    Implement the API handlers in api.cpp. Each handler constructs a JSON response from the mining core, speaker module, and SD module.

    Implementation steps:
    1. handleStatus():
       - Fetch current mining stats (hashrate, shares, pool, worker) from mining core
       - Call sdstore.getStatus() for SD capacity
       - Call speaker state getters for volume/mute status
       - Build JSON response with mining, sd, speaker, and system blocks
       - Serialize to JSON and send with Content-Type: application/json

    2. handleSpeaker() with method dispatch:
       - GET: return current speaker state (enabled, volume, muted)
       - POST: parse JSON body, apply operation (volume, mute, test-tone)
       - Call speaker.setVolume() or speaker.playTone() as requested
       - Return updated state

    3. handleSDList(request):
       - Get path query parameter (default "/")
       - Sanitize path via sdstore.sanitizePath()
       - Call sdstore.listFiles() to enumerate
       - Build JSON array of file objects with name, size, is_dir
       - Return JSON array

    4. handleSDDownload(request):
       - Get path query parameter
       - Sanitize path
       - Call sdstore.downloadFile() to read file
       - Allocate buffer, return content with correct Content-Type (detect from extension or default to binary)
       - Include Content-Length header
       - Free buffer after sending
       - Handle errors: file not found (404), too large (413)

    5. handleSDDelete(request):
       - Parse JSON body { path: string }
       - Sanitize path
       - Call sdstore.deleteFile()
       - Return { ok: bool, deleted: string }

    6. handleSDLog(request):
       - Get lines query parameter (default 100)
       - Call sdstore.readFile("/sd/mining_stats.csv")
       - Parse CSV (split by newlines, parse fields)
       - Return last N lines as JSON array (or paginate if large)

    Use ArduinoJson (https://arduinojson.org/) for JSON building if available in NerdMiner dependencies; otherwise use cJSON or custom serialization.
    Validate input: clamp lines to 1–10000, reject paths with NULs, etc.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request → API handler | Untrusted input from network; validate all query params, JSON bodies, file paths |
| API handler → SDStore | API requests file operations; enforce path sanitization before calling SDStore |
| API handler → Speaker | API requests tone playback; validate frequency and duration to prevent DoS |
| API handler → Mining core | API reads mining stats; read-only, low risk (no state mutation) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-12 | Injection | Path traversal in /api/sd/* | mitigate | Validate path parameter: reject "..", leading "/", absolute paths. Call sdstore.sanitizePath() before any file operation. Test with injection: ?path=../../config, ?path=/../secrets.h (all must be rejected). |
| T-08-13 | Denial of Service | Unbounded file download | mitigate | Enforce max download size (e.g., 10 MB). Return 413 if file exceeds limit. Validate file size before allocating buffer. |
| T-08-14 | Denial of Service | API call hammering | accept | ESP32 is single-threaded mining device; heavy API load will impact hashrate. Mitigation: rate-limiting not implemented (low priority; user controls who can access the device). Log API errors for monitoring. |
| T-08-15 | Information Disclosure | Listing files in /sd | accept | /api/sd/list reveals filenames (config.json, mining_stats.csv, etc.). Acceptable because the device is on a trusted LAN; if attacker can reach the API, they can already mount the SD physically. Do NOT expose paths outside /sd. |

</threat_model>
