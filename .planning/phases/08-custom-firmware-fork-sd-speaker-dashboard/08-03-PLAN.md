<task type="auto">
  <name>Task 2: Implement sdstore.cpp with VSPI FAT32 driver</name>
  <files>firmware/custom/NerdMiner-CYD-Custom/src/sdstore.cpp</files>
  <action>
    Implement the SDStore module using ESP-IDF's SPI and FatFS drivers. VSPI (SPI2) is available and not used by the main display/touch interface.

    Implementation steps:
    1. SDStore::mount():
       - Initialize VSPI bus (GPIO5=CS, 18=CLK, 19=MISO, 23=MOSI)
       - Attach SD card (sdspi_host_t with DMA, 20 MHz clock)
       - Mount FAT32 filesystem at /sd
       - Return true on success; log errors if SD not present

    2. SDStore::getStatus():
       - Call f_getfree() or equivalent to query total and free space
       - Return SDStatus struct with mounted flag and byte counts

    3. SDStore::writeConfig(const char* json_str):
       - Open /sd/config.json in write mode
       - Write json_str
       - Close file; return true on success
       - Overwrite if file exists (no append)

    4. SDStore::readConfig(char* buffer, size_t max_len):
       - Open /sd/config.json in read mode
       - Read up to max_len bytes into buffer
       - Null-terminate and close file; return true on success
       - If file doesn't exist, return false (caller may use defaults)

    5. SDStore::appendCSVLog(const char* csv_row):
       - Open /sd/mining_stats.csv in append mode
       - Write csv_row with newline
       - Close file; return true
       - Implement rotation: if file exceeds (e.g.) 1 MB, rename to .csv.1 and start fresh

    6. SDStore::listFiles(const char* dir, vector<string>& filenames, bool include_dirs):
       - Sanitize dir path
       - Use DIR/dirent or f_opendir() to iterate directory
       - Populate filenames vector (skip if not include_dirs and entry is a directory)

    7. SDStore::deleteFile(const char* path):
       - Sanitize path
       - Use f_unlink() or remove() to delete
       - Return true on success

    8. SDStore::downloadFile(const char* path, uint8_t*& buffer, size_t& size):
       - Sanitize path
       - Check file size; abort if exceeds (e.g.) 10 MB (DL size limit)
       - Allocate buffer via malloc or Arduino memory manager
       - Read entire file into buffer
       - Return true on success; caller responsible for freeing buffer

    9. sanitizePath(const char* path):
       - Remove leading slashes
       - Reject "..", absolute paths, and paths outside /sd
       - Return safe relative path or empty string on rejection

    Reference: witnessmenow/ESP32-Cheap-Yellow-Display examples for VSPI setup; ESP-IDF FatFS docs.
    Log all errors (SD not present, mount failure, file ops) for debugging.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mining core → SDStore module | Mining thread calls SD file ops; must be non-blocking or async to avoid delays |
| config.json on SD → WiFi/pool settings | User-supplied config file; validate JSON schema and value ranges |
| Web API → SDStore file ops (later task) | HTTP requests can request arbitrary file paths; path sanitization essential |
| GPIO23/19/18/5 → SD card | SPI bus communication; physical SD card may be absent or corrupted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-07 | Tampering | Path traversal in file browser | mitigate | Implement sanitizePath() strictly: reject "..", leading "/", and paths outside /sd. Validate in listFiles(), deleteFile(), downloadFile() before I/O. Test with injection: "../../etc/passwd", "//sd/config", "config.json/../../../" (all must be rejected or normalized). |
| T-08-08 | Tampering | Malicious config.json | mitigate | Schema validation: parse config.json, check required fields and types. Validate WiFi SSID length (<32 chars), reject NULs. Validate pool URL format (regex or URL parser). Log parsing errors. |
| T-08-09 | Information Disclosure | Wallet address in CSV or config | mitigate | CSV logging logs hashrate and shares, NOT wallet address. config.json on SD contains user's WiFi password and pool config (user responsibility to protect SD). .gitignore prevents config.json from being committed. |
| T-08-10 | Availability | SD card fills up | mitigate | CSV logger includes rotation (rename to .csv.1 when file exceeds 1 MB). Implement size check before write; if SD fills, log error and continue mining (SD-loss is non-fatal). |
| T-08-11 | Availability | SD card absent/corrupted | accept | Graceful degradation: if mount fails, log warning and continue (mining works without SD). If config.json absent, use defaults. If CSV write fails, log and continue. SD is a convenience feature, not a hard requirement. |

</threat_model>
