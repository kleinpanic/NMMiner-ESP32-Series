  <name>Task 1: Security review of firmware modules (path sanitization, input validation, secret leakage)</name>
  <files>firmware/custom/NerdMiner-CYD-Custom/src/, firmware/custom/NerdMiner-CYD-Custom/include/</files>
  <action>
    Review all custom firmware modules (speaker, sdstore, api) for security issues. Use code inspection and grep patterns to identify common vulnerabilities.

    Checklist:
    1. Path traversal (CVSS 7+):
       - sdstore.cpp: grep for sanitizePath() calls in listFiles(), deleteFile(), downloadFile(), readConfig()
       - Ensure sanitizePath rejects: "..", absolute paths, paths outside /sd
       - Test sanitizePath with injection: "../../config", "//etc/passwd", "/sd/../../../", "config.json\x00.exe"
       - Verdict: PASS if all file ops are guarded by sanitizePath()

    2. Input validation:
       - api.cpp: verify volume_percent is clamped to 0–100, freq_hz to reasonable range (e.g., 100–5000 Hz)
       - api.cpp: verify CSV lines query parameter clamped to 1–10000 (prevent resource exhaustion)
       - api.cpp: verify JSON parsing handles errors (malformed JSON should return 400, not crash)
       - Verdict: PASS if all numeric inputs are validated before use

    3. Secret leakage:
       - Check .gitignore: config.json, secrets.h, flash backups must be ignored
       - Grep for hardcoded secrets: search for BTC addresses, WiFi passwords, API keys in source
       - Verdict: PASS if no secrets found in source and .gitignore covers them

    4. Buffer overflows / integer overflow:
       - sdstore.cpp: downloadFile() must check file size before allocating buffer (prevent OOM)
       - speaker.cpp: playTone() duration_ms should be validated to reasonable max (e.g., 30 seconds)
       - Verdict: PASS if size checks and limits in place

    5. Denial of Service:
       - api.cpp: check if endpoints validate request size (Content-Length, file size)
       - speaker.cpp: playTone() must auto-stop after duration (not infinite)
       - Verdict: PASS if DoS vectors have mitigations

    Document findings in firmware/custom/NerdMiner-CYD-Custom/SECURITY.md (or inline comments if minor).
  </action>

<task type="auto">
  <name>Task 2: Optimization review (mining hashrate, SD/speaker module overhead)</name>
  <files>firmware/custom/NerdMiner-CYD-Custom/src/main.cpp, firmware/custom/NerdMiner-CYD-Custom/src/speaker.cpp, firmware/custom/NerdMiner-CYD-Custom/src/sdstore.cpp</files>
  <action>
    Review the firmware for performance issues that might degrade mining hashrate or introduce latency.

    Checklist:
    1. Mining loop:
       - Verify speaker.cpp playTone() is non-blocking (uses LEDC, not delay())
       - Verify sdstore.cpp appendCSVLog() is non-blocking or runs in background task (does not stall mining loop)
       - Grep main.cpp for delay() or blocking calls in mining task; should be minimal

    2. Memory usage:
       - Check if speaker module allocates large buffers (should not); LEDC uses PWM registers, not RAM
       - Check if sdstore module allocates unbounded buffers; file I/O should use streaming or bounded buffers

    3. Synchronization:
       - If speaker or SD operations run in separate FreeRTOS tasks, check for deadlocks or race conditions on shared state
       - Mining core reads should use read-only access (no locks needed)

    4. Compile-time optimization:
       - Confirm platformio.ini includes -O2 (or -O3) optimization flag for release build
       - Verify unused code is stripped (LTO/link-time-optimization recommended)

    Benchmark (post-flash, verified separately):
       - Flash and measure hashrate: should match baseline (stock NerdMiner v2.0.02) within <5% variance
       - If hashrate drops >5%, profile CPU usage (Arduino Serial monitor or ESP-IDF monitor to identify bottleneck)

    Document findings in firmware/custom/NerdMiner-CYD-Custom/OPTIMIZATION.md or inline comments.
  </action>
  <verify>
    <automated>
      grep -v 'delay.*\(1\|10\|100\)' firmware/custom/NerdMiner-CYD-Custom/src/main.cpp | grep -q 'delay' || echo "No blocking delays found (good)" && \
      grep -q '\-O2\|-O3\|optimize' firmware/custom/NerdMiner-CYD-Custom/platformio.ini
    </automated>
  </verify>
  <done>
    Optimization review completed.
    Speaker module is non-blocking (LEDC PWM).
    SD module uses async I/O or background tasks (does not stall mining).
    Memory allocation is bounded (no OOM risks).
    Compiler optimizations (-O2/-O3) enabled.
    Mining hashrate expected to be within <5% of baseline.
  </done>

  <name>Task 6: Write FLASH_GUIDE.md with step-by-step flashing instructions</name>
  <files>firmware/custom/NerdMiner-CYD-Custom/docs/FLASH_GUIDE.md</files>
  <action>
    Create a user-friendly flashing guide that emphasizes backup-first safety and includes step-by-step commands.

    Sections:
    1. Prerequisites:
       - ESP32-2432S028R CYD device with USB-C connection to computer
       - Python 3 + esptool installed: `pip install esptool`
       - Firmware binary: build/esp32-2432s028r-st7789/firmware.bin
       - Backup of current firmware (if upgrading from stock NMMiner)

    2. Backup Current Firmware (CRITICAL):
       ```bash
       esptool.py -p /dev/ttyUSB0 read_flash 0x0 0x400000 backup.bin
       # Windows: COM3 or COM4 instead of /dev/ttyUSB0
       ```
       Save backup.bin to hardware/backups/ for safekeeping.

    3. Flash Custom Firmware:
       ```bash
       esptool.py -p /dev/ttyUSB0 write_flash 0x10000 firmware.bin
       ```
       Or via PlatformIO:
       ```bash
       cd firmware/custom/NerdMiner-CYD-Custom
       platformio run --target upload -e esp32-2432s028r-st7789
       ```

    4. Verify Flash:
       - Device should reboot (watch serial console: `esptool.py -p /dev/ttyUSB0 monitor`)
       - Display should show NerdMiner UI (no crash loops)
       - Miner should begin hashing

    5. Rollback (if issues):
       - Flash backup: `esptool.py -p /dev/ttyUSB0 write_flash 0x0 backup.bin`
       - Device reverts to previous state

    6. Troubleshooting:
       - "Device not found": check USB cable, driver, correct port (/dev/ttyUSB0 or COM3)
       - "Flash error": device may be in boot mode; press RESET or BOOT button and retry
       - "Display corruption": re-flash; if persists, restore backup

    Include warnings:
       "BACKUP BEFORE FLASHING. Custom firmware is not signed by official NMMiner team. Flash at your own risk."
       "If mining stops or display fails, restore the backup firmware."
  </action>
