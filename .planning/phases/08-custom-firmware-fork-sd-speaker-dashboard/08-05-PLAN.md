<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Flask proxy | Dashboard sends user commands (volume, file delete); proxy must validate before forwarding to firmware |
| Flask proxy → Firmware API | Proxy forwards requests; must not expose sensitive headers or raw firmware errors to browser |
| Browser → File download | User requests file download; browser receives binary; validate Content-Length and reject oversized responses |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-16 | Injection | Path traversal in file delete | mitigate | UI only sends sanitized paths (from firmware's listFiles response). Firmware re-sanitizes before delete (defense in depth). Do NOT construct paths in JavaScript from user input. |
| T-08-17 | Information Disclosure | Firmware error details to browser | mitigate | Flask proxy catches firmware errors and returns generic "request failed" messages. Log detailed errors server-side only. Do NOT expose firmware stack traces to browser. |
| T-08-18 | Tampering | Reflected XSS in file list | mitigate | Escape filename when rendering in JavaScript: use textContent or DOMPurify, not innerHTML. File names from firmware are user-supplied (via SD, untrusted); assume they may contain <script> or other markup. |

</threat_model>
