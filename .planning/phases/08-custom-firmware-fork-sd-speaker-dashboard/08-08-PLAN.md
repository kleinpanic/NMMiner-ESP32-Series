<task type="auto">
  <name>Task 1: Flash custom firmware via esptool</name>
  <files>/dev/ttyUSB0 (firmware partition at 0x10000)</files>
  <action>
    Flash the custom firmware binary to the device using esptool. This overwrites the mining firmware but leaves the NVS partition (WiFi/pool config) intact.

    Steps:
    1. Verify device is still connected and responsive:
       ```bash
       esptool.py -p /dev/ttyUSB0 flash_id
       ```
       Should output chip ID (ESP32) and flash size (4 MB typical).

    2. Flash firmware binary at offset 0x10000:
       ```bash
       esptool.py -p /dev/ttyUSB0 write_flash 0x10000 \
         firmware/custom/NerdMiner-CYD-Custom/build/esp32-2432s028r-st7789/firmware.bin
       ```

    3. Wait for flash to complete (1–2 minutes); should show "Leaving... Hard resetting via RTS pin" at the end.

    4. Expect device to reboot automatically; watch serial output for boot messages:
       ```bash
       esptool.py -p /dev/ttyUSB0 monitor
       ```
       Should see:
       - ESP32 boot sequence
       - WiFi connecting to "Homebase"
       - Pool connection to pool.nerdminers.org:3333
       - Mining loop starting
       - Display updates

    5. If device doesn't boot:
       - Wait 10 seconds (slow boot after flash is normal)
       - If still no output after 30 seconds: press RESET button on device
       - If persists: restore backup (see rollback task)

    Do NOT interrupt the flashing process once started.
  </action>
  <verify>
    <automated>
      esptool.py -p /dev/ttyUSB0 flash_id 2>&1 | grep -q 'Detected flash size' && \
      esptool.py -p /dev/ttyUSB0 write_flash 0x10000 \
        firmware/custom/NerdMiner-CYD-Custom/build/esp32-2432s028r-st7789/firmware.bin && \
      sleep 5 && \
      timeout 30 esptool.py -p /dev/ttyUSB0 monitor 2>&1 | grep -q 'WiFi\|mining\|pool' || echo "Flashing started; manual verification required"
    </automated>
  </verify>
  <done>
    Firmware flashed to offset 0x10000.
    Device boots (serial output shows WiFi and pool connection).
    No immediate crash loops.
  </done>
</task>

| Boundary | Description |
