<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator -> physical device (USB serial) | Only a person with physical USB access can flash/back up; every esptool op resets the chip and interrupts live mining |
| Backup .bin -> filesystem/git | The 4 MB dump is the closed stock image — must never leave the machine or enter version control |
| Flashed image -> bootable device | A bad/partial write or wrong driver can leave the device non-booting (brick) until restored |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Denial of Service | live mining during backup/flash | accept | D-70 go-ahead gate makes the ~45-60s mining interruption an explicit user-authorized event, not a surprise; documented in 07-VALIDATION.md |
| T-07-02 | Information Disclosure | hardware/backups/*.bin (closed stock image) | mitigate | Dir gitignored (.gitignore:8); T2/T7 verify the .bin is NOT staged (`git status` check); no-redistribution per D-11/RE-04 — never committed, never shared |
| T-07-03 | Tampering | flashed firmware integrity | mitigate | T4 `verify_flash` byte-compares all 3 offsets against on-disk artifacts before trusting the device; T3 requires "Hash of data verified" |
| T-07-04 | Denial of Service | brick / non-boot after flash or wrong ST7789 driver | mitigate | Fresh 4 MB backup taken BEFORE any write (T2); one-command restore documented + backup integrity proven (T7); ST7789 branch (T6) recovers a wrong-driver display |
| T-07-05 | Spoofing | identity/secrets on reconfig | accept | Pool + recovered wallet entered via WiFiManager portal / SD config.json at runtime; no secrets committed (D-74) |
| T-07-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this phase — runbook executes existing validated artifacts + esptool already in the fork venv; nothing to audit |
</threat_model>
