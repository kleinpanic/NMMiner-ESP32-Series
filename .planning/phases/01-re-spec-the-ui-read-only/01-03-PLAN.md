<definitions>
## "Key geometry" for the 4 non-priority screens (resolves MEDIUM)
For Loading/Config/Weather/SPrice (non-deep-spec per D-02): extract at minimum the screen's **3-5 primary content widgets** — the main/title label, 1-2 data/value fields, and the background/root object. NOT a full widget table (that back-fills in each screen's own phase). Each row still carries x/y where recoverable + a Confidence label.

## Pitfall-2 resolution procedure (resolves H4)
If a string->l32r literal address is NOT a function entry (lands mid-literal-pool, no prologue visible): in Ghidra, navigate to the literal address, then disassemble BACKWARD / use "Find Next Code" (or Listing FindPrev to the prologue) until the function prologue (entry / `entry a1, ...` on Xtensa) is found. RECORD the resolved function-entry address in SPEC.md alongside the literal address (e.g. "literal 0x400d1960 -> resolved entry 0x400d18f4"). The resolved entry is the canonical address for the screen.

## Per-table Confidence enforcement (resolves cycle-3 MEDIUM)
The verifier (Task 1) must NOT accept "the token `Confidence` appears somewhere in the file." It must assert a `Confidence` column header exists in EACH of these required tables/sections independently: (1) §Screen Inventory, (2) the Miner320x240 §Per-Screen Widget Geometry table, (3) the Clock320x240 §Per-Screen Widget Geometry table, (4) §Share-Accept Seam (the seam row), (5) §ss_render Characterization (the ss_render row), (6) §Font Inventory. SPEC.md authoring must therefore place a Confidence column on each of these tables, not a single global one.
</definitions>
