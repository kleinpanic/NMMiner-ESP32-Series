## Read-Only Invariant (binding for all of Phase 1)

"Read-only" for this phase means: **NO firmware writes, NO flashing, NO firmware build, NO device modification.** The closed stock image is analyzed; nothing is written back to any device or to firmware source.

Permitted committed code: **identifier-only RE helper scripts** — `scripts/nmminer_str_xref.py` (this plan) and `scripts/check_spec_screens.py` (Plan 03). These are the ONLY two committed files this phase produces. They are NOT firmware; they are analysis tooling. Each MUST contain ZERO verbatim closed-firmware strings/bytes — only addresses, **screen-CLASS-NAME identifiers** (class names / section names as functional search inputs — deemed functional identifiers, acceptable) and structural logic. Any NON-identifier recovered firmware literal (e.g. the share-accept format string `#%d share accepted, %ldms`, any other recovered string literal) MUST NOT appear in a committed script — it is supplied at runtime via a CLI argument or read from a gitignored input file under `hardware/recovered-assets/`. (Resolves H1 + cycle-3 HIGH.)

Everything else — the Ghidra project, WORKBENCH.md, SPEC.md, all `*.bin`/`*.elf`, decompiled C bodies — stays under gitignored `hardware/recovered-assets/` (.gitignore:25) or `~/ghidra_projects/` (outside repo). Never committed (RE-04).

**Stale-ref guard:** `.planning/research/STACK.md` and `SUMMARY.md` still cite dynacylabs loader **v12.0** / "Ghidra 11.x". That is stale. The locked, prebuilt-asset pairing is **Ghidra 11.3.1 + dynacylabs v11.3.1** (D-06 correction). WORKBENCH.md MUST state "v12.0 intentionally not used (no prebuilt asset)" so a downstream agent reading the stale canonical refs does not follow them.
</phase_boundary>
