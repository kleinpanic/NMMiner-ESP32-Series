# Retrospective

## v4.0 — PanicMiner

Shipped an owned open mining application and matching UI for the observed ESP32-2432S028R, with accepted work, measured performance, persistent configuration and SD-equipped charger startup. The canonical repository and release preserve source, checksums, licenses and bounded verification evidence.

Native diagnostics resolved the misleading certificate error as RSA workspace allocation failure under fragmented heap. Separately testing touch press/release, SD/TLS memory pressure, forced pool failover and actual charger startup found failures that successful compilation could not establish. Strict work-counter measurements kept the agreed 5% performance limit meaningful.

The work took too many owner interactions and mixed stale pending notes with later fixes. Future hardware milestones should name the image hash, power source and exact acceptance evidence in one record from the start, preserve failed observations, and ask only for physical steps that cannot be performed remotely. Reserve bounded TLS/SD memory before adding presentation features.

Current-image 20-minute qualification and charger observation retain their own scope; the previous image owns its independent one-hour result. IPv6 destination decoding and Espressif radio/ROM are explicit limits. Zero formal plans were created; archived summaries describe the completed work retrospectively. Session cost and model usage were not measured.

No next milestone has been requested.
