# PanicMiner v4.0.0-rc.2

This update adds setup-portal pool failover, deliberate RGB status and a native
network-header audit. The tested application is installed and mining with SD.

## Verified in this follow-up

- Setup opened through the saved LAN connection. Both pool endpoints survived
  saving and reboot. Three deliberate primary connection failures switched to
  the fallback, which authorized and completed work. The original primary and
  unchanged payout address were restored; fallback remains disabled unless set.
- The actual GPIO output latches showed green while authorized, amber while
  waiting, and both phases of the offline red blink. Pool and SD recovered after
  the controlled board-only Wi-Fi drop. The 800 ms cyan share path passes the
  production C++ tests, including persisted counts and clock wrap.
- The owner confirmed working audio. The unchanged speaker path stays quiet at
  boot/reconnect and chirps only for confirmed events; host tests cover priority,
  mute, cancellation, bounds and wrap. No fake share or payout was generated.
- Steady-boot outbound-header audit: 2,023 packets, 6 IPv4
  endpoint entries, zero overflow, unparsed frames or unknown IPv4 destinations.
  The audit counted 2 IPv6 frames without decoding their destinations. Observed
  services matched configured Stratum, mempool.space
  HTTPS, NTP, local DNS and HTTP replies to the LAN client. ARP is accounted for.
  The separate reconnect test also observed DHCP and two counted IPv6 frames;
  those IPv6 destinations were not decoded. The audit starts after saved Wi-Fi
  initialization and retains no payloads. NTP attribution follows the firmware's
  sole NTPClient UDP/123 path; this does not audit radio management or chip ROM.
- Exact-image Mine retest: **1,201.807 seconds, 220 samples, 968.720 kH/s (-2.54% against 994); all 17 strict checks passed**. SD added 20
  records, wallet data stayed current, and there were no API/native faults,
  reboot or SHA mismatch. One new share was accepted. The post-window CSV contained
  773 complete nine-column records.
- Three complete live-feed cycles, all five pages and 24 SD private-path guards
  passed before the timed run. C++ ASan/UBSan, both firmware targets, restore
  safety, both UI themes and public CI passed. Python: 108 local tests and
  29 subtests; public CI has 107 tests, 29 subtests and one explicit private-image
  skip. No new dependency was needed. Binary/history/private-value scans passed.

The earlier mining-core/SD image in rc.1 passed a separate **60.24-minute** soak
at **967.925 kH/s** with a newly accepted share. That is evidence for its recorded
image, not a claim that this follow-up image ran that same hour. Exact identities
and preserved failures are in the [validation record](../panicminer-validation-2026-11-25.md).

## Identity and use

Firmware source: `07c3931cbcb297f330eabe68e7feabbc2f330c2f`. Application: 1,797,328 bytes,
SHA-256 `0e32d00af0c9cb8d996f1a284cc9a04768707402d336ae5ec8f9e64c4c27b835`. The full 4 MB pre-write backup was independently verified, as
were all four written images. The release bundle includes matching factory
inputs, checksums and license notices; it contains no device configuration.

USB power loads the saved 2.4 GHz Wi-Fi and pool automatically. Allow about a
minute for rolling hashrate windows to fill. BOOT hold opens Setup without
clearing settings. Primary and optional fallback use the same configured payout
address. Shares confirm work and are not payments; wallet values describe that
address's funds. No private key or seed is used.

## One physical check remains

This follow-up used laptop USB and saved-settings EN resets with SD inserted.
An earlier charger cold boot was verified before the SD changes. A new actual
**charger power removal/reinsertion with SD** still needs physical access; an EN
reset cannot establish that result. Audio, portal/fallback persistence, LED
outputs and the steady-window IPv4 egress checks are no longer pending. The full
hardware milestone stays open only for that physical check.

The qualified target is this observed ESP32-2432S028R with its recorded panel
configuration. The application source is open; Espressif radio binaries and ROM
remain platform components. Read the [README](../../README.md) and
[provenance](../firmware-provenance.md) before building or restoring.
